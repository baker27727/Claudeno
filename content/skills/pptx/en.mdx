## What it does and why it exists

This skill teaches Claude a complete workflow for any task touching a `.pptx` file — whether reading, creating, or editing one. It covers three core paths:

- **Reading**: extract text with `markitdown`, generate a visual thumbnail overview, or unpack the raw XML for inspection.
- **Editing**: work from an existing template or reference deck — unpack, manipulate slides, edit content, clean, and repack.
- **Creating from scratch**: use `pptxgenjs` when no template exists.

Beyond mechanics, the skill embeds a detailed design system (color palettes, layout patterns, typography pairings, spacing rules) so generated decks avoid the "boring AI slide" look — and a mandatory QA loop (content check + visual inspection via rendered images, ideally with subagents) before declaring a deck finished. The skill triggers any time a `.pptx` file is input, output, or mentioned — even if the extracted content is just being reused elsewhere, like in an email.

## Install

```bash
npx skills add anthropics/skills/pptx
```

Requires several external tools to function fully:

```bash
pip install "markitdown[pptx]"    # text extraction
pip install Pillow                # thumbnail grids
npm install -g pptxgenjs           # creating decks from scratch
# LibreOffice (soffice) — PDF conversion, for visual QA
# Poppler (pdftoppm)   — PDF to images, for visual QA
```

Editing and QA scripts (`thumbnail.py`, `unpack.py`, `soffice.py`) ship with the skill under `scripts/`.

## Safety and permissions

- **Executes local scripts and CLI tools** (`markitdown`, `python` helper scripts, `soffice`, `pdftoppm`) — review what commands Claude runs, especially `soffice --headless` conversions.
- **Reads and writes files** in your project directory — unpacking a `.pptx` creates a working directory of raw XML; packing overwrites/creates output `.pptx` files. Back up originals before large edits.
- No network access is required by the skill itself; all dependencies are installed once via pip/npm ahead of time.
- Because unpacking exposes raw slide XML, treat that intermediate directory as sensitive if the presentation contains confidential content — clean it up after use.

## Practical use cases

- Extracting and summarizing text from a `.pptx` for a report or email, without opening PowerPoint.
- Rebranding a company template into a new pitch deck with consistent colors, fonts, and layouts.
- Generating a fully new slide deck from scratch (no template) for a talk or investor pitch.
- Combining or splitting slide files, or updating speaker notes and comments across a deck.
- Running a rigorous visual QA pass (via rendered slide images) to catch overlapping text, low-contrast elements, or leftover placeholder text before delivery.

## Limitations

- Requires several external dependencies (`markitdown`, `Pillow`, `pptxgenjs`, LibreOffice, Poppler) — not usable out of the box without setup.
- Visual QA depends on rendering to PDF/images via LibreOffice and Poppler; without these, only content-level (text) QA is possible.
- The design guidance (palettes, fonts, layouts) is prescriptive advice baked into the skill, not a guarantee of visual perfection — a manual review pass is still recommended.
- Editing existing templates involves manipulating raw OOXML; complex or unusual template structures may require manual intervention beyond the scripted workflow.

## Source update

The skill now includes a comprehensive design system embedded in the workflow: eleven curated color palettes (Midnight Executive, Forest & Moss, Coral Energy, etc.) indexed by topic, typography pairings using safe fonts (Calibri, Cambria, Arial) with QA reliability notes, standardized spacing rules (0.5" margins, 0.3–0.5" gaps), and layout patterns (two-column, icon + text rows, grid layouts) to avoid generic AI-generated aesthetics. A new "Avoid" section calls out common visual mistakes: accent bars under titles, decorative stripes, cream/beige defaults, and text overflow. The QA section now mandates both content checks (markitdown + placeholder grep) and visual inspection via LibreOffice-rendered slide images, with detailed defect categories (overlap, contrast, alignment, margins).
