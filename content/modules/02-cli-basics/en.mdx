# CLI Basics

The `claude` CLI has dozens of flags, but you'll reach for a handful of them
constantly. This module covers those — the rest are worth skimming in
`claude --help` once, not memorizing.

## Check your version

```bash
claude --version
```

Useful when a doc or teammate refers to a specific version — behavior genuinely
changes between releases.

## Run a single request (print mode)

```bash
claude -p "list the files in this repo"
```

`-p` (or `--print`) sends one request, prints the answer, and exits — no interactive
session. This is the mode scripts and CI pipelines should use, since there's no prompt
waiting for input.

<Callout type="tip" title="Tip">
  Print mode composes with shell pipes: `cat error.log | claude -p "what's wrong here?"`
  feeds file content straight in.
</Callout>

## Resuming sessions: -c vs -r

Two flags resume past work, and picking the wrong one wastes time.

```bash
claude -c
```

`-c` (or `--continue`) resumes your **most recent** session in the current directory —
no picker, no name needed. Fastest option when you know it's the last thing you were
doing.

```bash
claude -r "fix-login-bug"
```

`-r` (or `--resume`) resumes a **specific** session by ID or name — useful once you
have more than one session going in the same project.

<Callout type="mistake" title="Common mistake">
  Reaching for `-c` when you actually want a named session from earlier in the week —
  it only ever grabs the latest one. Use `-r` with a name or ID instead.
</Callout>

## Picking a model for this session

```bash
claude --model sonnet
```

`--model` overrides your saved default for just this session — handy for comparing
model behavior on the same task without changing your global preference. (The
in-session equivalent is [`/model`](/en/learn/slash-commands).)

## Flags at a glance

| Flag | What it does |
|---|---|
| `--version`, `-v` | Print the installed CLI version |
| `--print`, `-p` | Run one request, print the result, exit |
| `--continue`, `-c` | Resume the most recent session, no picker |
| `--resume`, `-r` | Resume a specific session by ID or name |
| `--model` | Set the model for this session |
| `--verbose` | Enable verbose logging, useful when troubleshooting |
| `--settings` | Point at a settings JSON file or inline JSON |
| `--add-dir` | Grant access to an extra working directory |

## Key takeaways

- `-p` is for scripts and pipelines; it never opens an interactive session.
- `-c` resumes the latest session automatically; `-r` lets you pick by name or ID.
- `--model` changes the model for one session only, without touching your default.

## What's new in v2.1.204

**What's new (2.1.204):** This release is a targeted fix for headless sessions: hook events (such as `SessionStart`) now stream properly instead of stalling, preventing remote workers from being idle-reaped mid-hook.

## What's new in v2.1.210

Claude Code 2.1.210 now shows a live elapsed-time counter in the collapsed tool summary line for long-running tool calls, so they visibly tick instead of appearing stuck. Additionally, the `claude attach` kommando has been improved to wait for the daemon to settle and apply terminal resizes once attachment completes, reducing "job not found" or "agent is still starting" errors during session transitions.

## What's new in v2.1.211

Claude Code 2.1.211 introduces the `--forward-subagent-text` flag and `CLAUDE_CODE_FORWARD_SUBAGENT_TEXT` environment variable. When enabled, subagent text and thinking are included in stream-json output, providing more detailed insight into subagent reasoning during automation.

## What's new in v2.1.212

**New `claude auto-mode reset` command**: Restore the default auto-mode configuration with a confirmation prompt (pass `--yes` to skip). **MCP tool auto-background**: Tool calls running longer than 2 minutes now move to the background automatically so your session stays usable. Configure the threshold or disable with `CLAUDE_CODE_MCP_AUTO_BACKGROUND_MS`.

## What's new in v2.1.217

Claude Code now supports emoji shortcode autocomplete in the prompt input — type `:heart:` to insert ❤️, or `:hea` for suggestions. You can disable this with the `emojiCompletionEnabled` setting. Additionally, the CLI now warns you when transcript writes are failing (e.g. due to disk full) or when session saving is off due to an inherited environment variable, preventing silent data loss.

## What's new in v2.1.218

The `claude mcp list` and `/mcp` commands now display HTTP status and error text when a server fails to connect, and show warnings for MCP config values with hidden leading or trailing whitespace. Fixed the left arrow key discarding conversations with no undo—presses right after editing now confirm first, and Esc returns to the backgrounded conversation.

## What's new in v2.1.220

Claude Opus 5 is now the default Opus model (as of 2.1.219), featuring 1M context window and fast mode pricing at $10/$50 per million tokens. You can still use other models via `/model` or configuration; fast mode (`/fast`) now applies to Opus 5 and Opus 4.8.

## What's new in v2.1.222

**Focus view (VSCode, 2.1.221)**: A new chat-menu toggle hides tool activity behind an expandable per-turn summary with a live running-tool indicator; toggle with `Ctrl+Alt+F` or the "Claude Code: Toggle Focus view" command.

## What's new in v2.1.223

In cloud sessions, the `/teleport` hint now shows how to continue locally with `claude --teleport <session id>`, making it easier to transition your work between environments.

## What's new in v2.1.224

New in 2.1.224: The `claude self-hosted-runner` command turns your own machines or containers into a place Claude Code web, mobile, and desktop sessions can run (available on Team and Enterprise plans). Additionally, plugin installation now supports the `archive` source type, allowing you to install plugins from a zip over HTTPS without git or npm, with optional SHA-256 pinning.

## What's new in v2.1.226

Version 2.1.224 introduced `ListAgents` for discovering Claude Code sessions on other machines for cross-session messaging on macOS and Linux. Version 2.1.225 added a workspace trust prompt to `claude agents` for untrusted directories. Also in 2.1.225, gateway spend-limit support was added to usage warnings, which now display the spend cap, its reset time, and the operator's message.

**What's new in v2.1.227:** Performance has been improved with fewer event-loop stalls on file-not-found suggestions and at-mention size checks. Additionally, there was a fix for every Bash command failing under `claude-code-action` with `allowed_non_write_users` on GitHub-hosted runners.
