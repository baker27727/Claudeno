# MCP-tjenere

Model Context Protocol (MCP) er en åpen standard som kobler Claude Code til eksterne
verktøy, databaser og API-er — saksbehandlingssystemer, overvåkingsdashboard, CRM-er
og mer — slik at Claude kan handle direkte på dem i stedet for at du kopierer inn data
manuelt.

## Legg til en ekstern tjener (HTTP)

```bash
claude mcp add --transport http notion https://mcp.notion.com/mcp
```

De fleste hostede integrasjoner eksponerer et HTTP- (eller SSE-)endepunkt. Dette er
den enkleste måten å koble til en tredjepartstjeneste på.

## Legg til en lokal tjener (stdio)

```bash
claude mcp add --transport stdio myserver -- npx server
```

Stdio-tjenere kjører som en prosess på din egen maskin — bra for verktøy som trenger
direkte systemtilgang eller et tilpasset skript. Alt etter `--` sendes uendret til
den prosessen, atskilt fra Claudes egne flagg som `--transport` eller `--env`.

## Valg av transport

| Transport | Kjører hvor | Typisk bruk |
|---|---|---|
| `stdio` | Lokal prosess | Tilpassede skript, direkte systemtilgang |
| `http` / `sse` | Ekstern | Hostede SaaS-integrasjoner |
| `ws` | Ekstern, vedvarende | Tjenere som pusher hendelser uoppfordret |

## Valg av nivå (scope)

```bash
claude mcp add --transport http stripe --scope local https://mcp.stripe.com
```

`--scope` styrer hvem andre som ser denne tjeneren: `local` (standard) holder den
privat for deg i dette prosjektet, `project` skriver den til en committet `.mcp.json`
hele teamet ditt får, og `user` gjør den tilgjengelig på tvers av alle prosjektene du
jobber i.

<Callout type="mistake" title="Vanlig feil">
  Å legge til en tjener med API-nøkkel med `--scope project` — det committer
  tilkoblingskonfigurasjonen der hele teamet ditt (og git-historikken) kan se den. Bruk
  `local`- eller `user`-nivå for alt som er sensitivt med tanke på legitimasjon.
</Callout>

## Administrere tilkoblinger

```
/mcp
```

`/mcp` åpner den interaktive listen over MCP-tjenertilkoblingene dine. Send
`reconnect <server>` for å koble til på nytt en som falt fra, eller `enable`/`disable`
med et tjenernavn (eller `all`) for å endre tilkoblingsstatus uten å åpne dialogen.

## Oppsummering

- `stdio` kjører lokalt; `http`/`sse`/`ws` kobler til en ekstern tjener.
- `claude mcp add --transport <type> <name> <url>` er den generelle formen for
  eksterne tjenere; stdio-tjenere legger til `-- <command>` på slutten.
- `--scope` avgjør om en tilkobling er privat (`local`), delt med teamet ditt
  (`project`), eller tilgjengelig overalt du jobber (`user`) — velg bevisst for alt
  med legitimasjon.
- `/mcp` administrerer tilkoblinger uten å forlate økten din.

## Relaterte skills

MCP kobler Claude til eksterne systemer; skills lærer den arbeidsflyter som ofte *bruker* disse koblingene. Mange kuraterte skills passer naturlig sammen med en MCP-tjener. Se [Skills og SKILL.md](/no/learn/skills/) og [skills-katalogen](/no/skills/).

## Nytt i v2.1.206

MCP-tjenere konfigurert via `--mcp-config` eller `.mcp.json` respekterer nå korrekt per-tjener `request_timeout_ms`-innstillinger, noe som fikser timeoutproblemer der langvarige MCP-verktøykall tidligere ville tidsavbruddet på 60-sekunders standard i friske økter. OAuth MCP-tjenere krever ikke lenger manuell omautentisering etter ett enkelt mislykket tokenverdier. I tillegg fikser en kritisk retting at `--permission-prompt-tool` som peker på en MCP-tjener som krasjer med "MCP-verktøy ikke funnet" ved kaldstart før tjeneren er ferdig tilkoblet. De reserverte navnene "Claude Browser" og "Claude Preview" er blitt reservert for systembruk; brukerens konfigurerte MCP-tjenere kan ikke lenger registrere seg under noen av navnene.

## Nytt i v2.1.209

MCP-tjenere konfigurert med en tom URL vises nå som "ikke konfigurert" i `/mcp` i stedet for en konfigurasjonsfeil. Fikset OAuth MCP-tjenere som krevde manuell re-autentisering etter en enkelt mislykket token-refresh — de håndterer nå token-refresh-feil mer elegantly. Fikset `--permission-prompt-tool` som peker på en MCP-tjener som krasjet med "MCP tool not found" ved kald start før tjeneren er ferdig med tilkoblingen.

## Nytt i v2.1.218

Kommandoen /mcp og claude mcp list viser nå HTTP-status og feilmelding når en tjener ikke klarer å koble til. En ny advarsel varsler deg om MCP-konfigurasjonsverdier med skjult ledende eller etterfølgende mellomrom som kan forårsake tilkoblingsproblemer.

## Nytt i v2.1.220

Kommandoen `claude mcp list` og `/mcp` viser nå HTTP-statuskoder og feiltekst når en tjener ikke klarer å koble til. En advarsel varsler også brukere om MCP-konfigurasjonsverdier med skjult ledende eller etterfølgende mellomrom som kan forårsake tilkoblingsproblemer.

## Nytt i v2.1.221

Nytt i 2.1.221: MCP-tjenere fra `--mcp-config` er nå riktig tilkoblet før første tur i utskriftsmodus (`-p`). Kommandoen `claude mcp list` er forbedret til å vise HTTP-status og feilmelding når en tjener ikke klarer å koble til. Merk at oppføringer i administrert MCP allowlist/denylist med `${VAR}`-plassholdere nå løses fra oppstartsmiljøet og administrert-innstillingsmiljø i stedet for innstillingsfil-miljø.

## Nytt i v2.1.226

**Nytt i 2.1.226:** Self-hosted runnere er nå tilgjengelige på Team- og Enterprise-planer via kommandoen `claude self-hosted-runner`, noe som lar dine egne maskiner eller containere fungere som verter for Claude Code-økter. I tillegg muliggjør den nye `archive`-plugin-kilden plugin-installasjon fra zip-filer over HTTPS med valgfri SHA-256-pinning, uten å kreve git eller npm.

## Nytt i v2.1.228

**Forbedret OAuth-pålitelighet (2.1.225+):** MCP OAuth-tjenere på macOS er nå mer robuste — intermitterende nøkkelkjedelesetimeouts forårsaker ikke lenger gjentatte 401-feil som kunne tyde på at autentisering aldri lyktes. Utløpte eller manglende Google Cloud-legitimasjon for Vertex AI feiler nå raskt (innen sekunder) i stedet for å prøve på nytt i minutter.

## Nytt i v2.1.233

Nytt i 2.1.233: Fikset MCP v2-tilkoblinger som endelig åpnet abonnement/lytt-strømmer på nytt mot servere som avslutter langvarige strømmer på en fast tidsavbrudd (vanlig på serverless-verter).

## Nytt i v2.1.238

**Headers helper for MCP**: MCP-tjenere kan nå inkludere en `headersHelper`-kommando som produserer HTTP-hodinger (f.eks. nylig utstedte tokens) for katalog- og same-origin-arkivhentinger. I prosjekt `.mcp.json`-filer krever `headersHelper` at prosjektmappens tillitsdialog er blitt akseptert, og den kjøres uten arvede legitimasjonsomgivelsesvariabler.

## Nytt i v2.1.247

MCP-tjener-konfigurasjonssvikter blir nå bedre rapportert: på Bedrock-, Vertex AI- og Foundry-økter (og alle med telemetri deaktivert), blir Claude nå informert når en konfigurert MCP-tjener ikke klarte å koble til, i stedet for at systemet feilaktig konkluderer med at tjenestens verktøy ikke eksisterer.
