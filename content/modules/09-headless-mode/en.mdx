# Headless Mode & Automation

Add `-p` (or `--print`) to any `claude` command to run it non-interactively: Claude
answers once and exits, instead of opening a session. This is the flag behind
scripting, CI pipelines, and any workflow where nothing should wait for a human.

## A basic query

```bash
claude -p "What does the auth module do?"
```

All the usual CLI flags work with `-p`, including `--continue`, `--allowedTools`, and
`--output-format`.

## Pipe data through Claude

Headless mode reads stdin, so you can pipe data in and redirect the response out
like any other command-line tool:

```bash
cat build-error.txt | claude -p 'concisely explain the root cause of this build error' > output.txt
```

## Get structured output

Use `--output-format json` to get a structured response — the text result lands in
the `result` field, alongside session metadata and cost:

```bash
claude -p "Summarize this project" --output-format json
```

<Callout type="tip" title="Extract just the text">
  Pipe the JSON through a tool like `jq` to pull out a single field:

  ```text
  claude -p "Summarize this project" --output-format json | jq -r '.result'
  ```
</Callout>

## Auto-approve tools

In a script or CI job, no one is there to click "approve." Use `--allowedTools` to
let Claude use specific tools without prompting:

```bash
claude -p "Run the test suite and fix any failures" --allowedTools "Bash,Read,Edit"
```

## Continue a conversation across calls

`--continue` picks up the most recent conversation, so you can chain non-interactive
calls into a multi-step script:

```bash
claude -p "Now focus on the database queries" --continue
```

## Start faster with bare mode

```bash
claude --bare -p "Summarize this file" --allowedTools "Read"
```

`--bare` skips auto-discovery of hooks, skills, plugins, MCP servers, auto memory,
and CLAUDE.md — only flags you pass explicitly take effect. That makes a run
reproducible across machines, which is exactly what you want in CI: a teammate's
personal hook or a project's MCP server won't quietly change the result.

<Callout type="mistake" title="Common mistake">
  Running CI jobs without `--bare` and being surprised the output differs from
  machine to machine. Without it, `claude -p` loads the same context an interactive
  session would — including anything configured in the working directory or
  `~/.claude`.
</Callout>

## Summary

- `-p` / `--print` runs one query non-interactively and exits — the foundation of
  scripting and CI use.
- Headless mode reads stdin, so it composes with standard shell piping.
- `--output-format json` returns structured output with a `result` field, ready to
  parse with `jq` or similar.
- `--allowedTools` auto-approves specific tools since no one is there to click
  approve in a script.
- `--continue` chains non-interactive calls into a multi-step script.
- `--bare` skips local hooks/skills/plugins/MCP/memory for a reproducible CI run.

## What's new in v2.1.209

Fixed background sessions auto-named by accepting a plan now showing that name on their agent-view row. Fixed background sessions that entered a git worktree resuming blank after a cold reopen from the agent list. Background agents now upgrade to a new version in the background right after a Claude Code update, instead of paying a slow stale-session upgrade when you attach. Completed background agents now stay listed in `/tasks` until cleanup instead of vanishing the moment they finish. Attaching to a stopped background agent now shows its transcript immediately while the session warms up, instead of a blank "Session is starting" screen.

## What's new in v2.1.211

Screen reader mode is now available for accessibility: run `claude --ax-screen-reader`, set `CLAUDE_AX_SCREEN_READER=1`, or add `"axScreenReader": true` to settings. This enables plain-text rendering optimized for screen readers. Additionally, integer environment variables like timeouts and token budgets now accept scientific notation (e.g., `1e6`) and digit separators (e.g., `64_000`).

## What's new in v2.1.212

**WebSearch rate limiting**: A session-wide limit on WebSearch tool calls (default 200) stops runaway search loops. Tune via `CLAUDE_CODE_MAX_WEB_SEARCHES_PER_SESSION`. **Improved model switching**: Headless/SDK sessions now apply a `set_model` control request mid-turn; the next model round-trip uses the new model instead of waiting for the next turn.

## What's new in v2.1.216

Resumed background agent sessions now correctly restore the agent's full configuration, including its prompt and tool restrictions, instead of reverting to the default agent. This ensures consistent behavior across session checkpoints.

## What's new in v2.1.217

Remote Control sessions now properly display pending permission prompts and dialogs to viewers that connect after they appear. Background shells are more reliable and no longer become impossible to stop after a session is sent to the background or exits on heavily loaded systems. MCP and GitHub app installation commands in headless sessions now queue a "needs input" request in the agent view when no client is attached.

## What's new in v2.1.218

Headless and SDK sessions now preserve fork-session lineage after compaction, preventing loss of session relationships. When resuming a session with --resume or /resume, malformed delta attachments that previously caused every turn to fail or crash are now handled gracefully.

## What's new in v2.1.221

New in 2.1.221: Background sessions now commit and push to preserve work, open a draft PR only when the task explicitly calls for one, follow your CLAUDE.md git instructions, and always end by reporting where the work lives. MCP server errors from `--mcp-config` entries that fail config validation now appear in the headless stream-json init event under `mcp_server_errors`, with a startup warning printed in terminal runs.

## What's new in v2.1.226

## What's new in v2.1.228
