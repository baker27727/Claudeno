# Subagents

Subagents are specialized assistants that run a side task in their own context
window — with a custom system prompt, limited tool access, and independent
permissions — then return only a summary to your main conversation. Use one when a
task would otherwise flood your session with search results or logs you won't need
again.

## Anatomy of a subagent

```bash
cat .claude/agents/code-reviewer.md
```

```markdown
---
name: code-reviewer
description: Reviews code for correctness and style before a commit.
tools: Read, Grep
model: haiku
---
You are a meticulous code reviewer. Point out bugs, unclear naming, and
missed edge cases. Do not rewrite code yourself.
```

A subagent is just a markdown file: YAML frontmatter (`name`, `description`, `tools`,
`model`) followed by its system prompt as the body.

## Where subagents live

| Scope | Path |
|---|---|
| Project (shared with your team) | `.claude/agents/` |
| Personal (all your projects) | `~/.claude/agents/` |

Claude reads each subagent's `description` to decide when a task matches it, so write
a clear, specific description.

<Callout type="tip" title="Tip">
  Keep `tools` short and specific to the job. A code-reviewer that can only `Read` and
  `Grep` can't accidentally rewrite the file it's supposed to be critiquing — least
  privilege applies to subagents too.
</Callout>

<Callout type="note" title="Note">
  The `model` field accepts a shorthand (`sonnet`, `haiku`, `opus`) or `inherit` to use
  whatever model is driving the main conversation. Pick a cheaper model like `haiku`
  for high-volume, low-complexity checks.
</Callout>

## Creating one

```
/agents
```

In recent versions this no longer opens an interactive wizard — instead, ask Claude to
create the subagent for you, or create the markdown file in `.claude/agents/` by hand.

## Key takeaways

- A subagent is a markdown file with frontmatter — no special tooling to create one.
- Its `description` is what Claude matches against, not its file name.
- Limiting `tools` to what the job needs is the single biggest safety lever you have.
- It runs in its own context window and hands back only a summary, keeping your main
  conversation uncluttered.

## What's new in v2.1.204

**What's new (2.1.204):** In headless sessions, hook events (including `SessionStart` hooks) now stream correctly instead of stalling — this fixes an issue where remote workers could be idle-reaped in the middle of a hook running, which could interrupt subagent startup in background/headless workflows.

## What's new in v2.1.206

Background agents now upgrade to a new version in the background immediately after a Claude Code update, rather than paying a slow stale-session upgrade cost when you attach to them. Additionally, the agents view has been improved: the status column now uses the full terminal width instead of truncating at 64 characters, sessions now display a colored state word and a classifier-written headline instead of raw tool call text, and rows that edit, merge, comment on, or push to an existing PR now link it directly in the session list. Several critical bugs have been fixed, including background agents becoming permanently unresponsive when the daemon's økt token went stale (they now recover automatically), and sessions becoming stuck showing "Needs input" in the agent list after the question was already answered.

## What's new in v2.1.212

**Subagent spawn limits**: A per-session cap (default 200) now prevents runaway delegation loops. Override with `CLAUDE_CODE_MAX_SUBAGENTS_PER_SESSION`. Use `/clear` to reset the budget. **Deprecation**: The Task tool's `mode` parameter is now ignored; subagents inherit the parent session's permission mode by default.

## What's new in v2.1.216

Claude Code 2.1.216 fixes a race condition where background subagents could be cancelled if a high-priority message arrived during their startup window. Worktree-isolated subagents are now prevented from redirecting git operations into the shared checkout via git flags or environment variables.

## What's new in v2.1.217

Subagent spawning is now controlled by two new constraints: a per-session spawn cap (default 20, configurable via `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`) limits concurrent subagents to prevent unbounded fan-out, and nested subagent spawning is disabled by default (enable with `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH`). The `--max-budget-usd` flag now correctly stops background subagents — once the cap is reached, new spawns are denied and running agents are halted.

## What's new in v2.1.218

Subagent spawning is now capped at 20 concurrent agents per session (override with `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`) to prevent unbounded delegation loops. By default, subagents can no longer spawn nested subagents; enable deeper nesting with `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH`. Skills with `context: fork` now run in the background by default—opt out per skill with `background: false`.

## What's new in v2.1.220

**What's new in 2.1.220:** Subagents can now spawn nested subagents up to depth 3 by default (previously depth 1). This enables more complex delegation workflows. You can disable nesting by setting `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1`. Additionally, the spawn cap (default 20 concurrent subagents per session) can be customized via the `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` environment variable to prevent unbounded delegation.

## What's new in v2.1.222

**Nested subagent depth (2.1.219–2.1.222)**: Subagents can spawn nested subagents up to depth 3 by default (configure via `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH`). Org-restricted `model:` aliases now step down to the newest org-allowed model in the family instead of dropping to the parent model. Worktree isolation now applies to file edits and Bash in every session type, preventing destructive git commands against the main checkout.

## What's new in v2.1.226

**Workspace trust prompt:** Subagents now display a workspace trust prompt for untrusted directories, matching the behavior of the main `claude` agent. **Cross-session messaging:** Use `ListAgents` to discover Claude Code sessions on macOS and Linux, enabling subagents to message each other across machines with `SendMessage` (new in v2.1.224).
